# Self-Healing Machines
## ML-Powered Predictive Maintenance and Automated Work Order Management

A complete, beginner-friendly predictive maintenance application using the NASA CMAPSS turbofan engine dataset. Predicts Remaining Useful Life (RUL), detects anomalies, triages engine health, and auto-generates maintenance work orders — all tracked in a live Streamlit dashboard.

## 🔄 Running the Full Pipeline

Run all steps in order (recommended for first use):

```powershell
py -3 scripts/run_pipeline.py --step all
```

Or run individual steps:

```powershell
# Step 1: Load, validate, compute RUL, engineer features, fit preprocessor
py -3 scripts/run_pipeline.py --step preprocess

# Step 2: Train models (Linear, RF, GB), evaluate, save artifacts, log to MLflow
py -3 scripts/run_pipeline.py --step train

# Step 3: Run batch predictions on full dataset
py -3 scripts/run_pipeline.py --step predict

# Step 4: Apply triage rules to latest predictions
py -3 scripts/run_pipeline.py --step triage

# Step 5: Create maintenance work orders in SQLite
py -3 scripts/run_pipeline.py --step workorders
```

**Expected output after `--step all`:**
- `data/processed/train_features.csv`
- `data/processed/test_features.csv`
- `data/processed/predictions_latest.csv`
- `data/processed/triage_decisions.csv`
- `artifacts/models/<run_id>/` (model files)
- `artifacts/models/active_model.txt`
- `data/maintenance.db` (SQLite)
- `mlruns/` (MLflow tracking)
- Console output with actual MAE, RMSE, NASA score

## 📐 Evaluation Metrics Explained

All metrics are computed from **actual model predictions** — never hardcoded.

| Metric | Formula | Better |
|---|---|---|
| MAE | Mean absolute error (cycles) | Lower |
| RMSE | Root mean squared error (cycles) | Lower |
| NASA Score | Asymmetric: underestimates penalized less than overestimates | Lower |

**NASA Score formula:**
```
d = predicted_RUL - true_RUL
s = exp(-d/13) - 1   if d < 0  (early prediction, less penalty)
s = exp(d/10) - 1    if d >= 0 (late prediction, heavy penalty)
Score = sum(s) across all test engines
```

## 🤖 Triage Rules Reference

| Condition | Severity | Action |
|---|---|---|
| Invalid/NaN input | DataQuality | Reject, flag data issue |
| RUL ≤ 15 cycles | Critical | Emergency maintenance now |
| 15 < RUL ≤ 40 cycles | Warning | Planned maintenance soon |
| RUL > 40 + anomaly detected | InspectionReview | Manual sensor inspection |
| RUL > 40, no anomaly | Normal | Continue monitoring |

Thresholds are configurable in `config/settings.yaml`.

## 🔧 Configuration

Edit `config/settings.yaml` to adjust:
- RUL cap value (default: 125 cycles)
- Triage thresholds (critical: 15, warning: 40 cycles)
- Anomaly detection contamination and threshold percentile
- Selected sensor channels
- Rolling window sizes
- Model hyperparameters
- MLflow experiment name

## 🐛 Troubleshooting

| Problem | Solution |
|---|---|
| `ModuleNotFoundError: src` | Run scripts from the `self-healing-machines/` directory |
| `FileNotFoundError: CMAPSSData` | Check `paths.raw_data_dir` in `config/settings.yaml` |
| Dashboard shows empty state | Run `py -3 scripts/run_pipeline.py --step all` first |
| SQLite locked error | Close any DB viewers holding the file |
| MLflow import error | Run `py -3 -m pip install mlflow` |
| Streamlit port busy | Use `streamlit run app.py --server.port 8502` |

## ⚠️ Important Disclaimers

- **Simulation only**: No real-time sensor connection is implemented.
- **Triage thresholds**: The 15 and 40-cycle limits are demonstration values, not validated engineering standards.
- **Anomaly detection**: No ground-truth anomaly labels exist in CMAPSS; precision/recall are not reported.
- **Dataset**: FD001 is a simulation of turbofan engine degradation, not real operational data.
- **Model metrics**: All numbers shown are computed from actual predictions — none are hardcoded.
